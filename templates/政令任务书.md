# 政令任务书（通译司产物）

> **使用对象**：政令台在每个政令的通译阶段填写，用户确认后进入流转阶段。
> **门禁硬约束**：本任务书未经用户确认 → 流转司不得开始（参见 SKILL.md §2-①）。

## 为什么是这个五字段

| 字段 | 解决的问题 |
|---|---|
| 意图(What) | 让 AI 与用户对"做什么"达成同一句理解（最容易出歧义的地方） |
| 目的(Why) | 决定"什么样的交付算好"——比 What 多一层"评判视角" |
| 范围(Scope) | 显式划界，避免 AI 自行加戏 |
| 验收标准(Accept) | 把"好"翻译成"可勾选"的条款，验收司才能机械对照 |
| 未知项(Unknown) | 把"我不知道什么"显式列出，避免静默假设 |

---

## 字段规范

| 字段 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `意图(What)` | string | ✅ | 用一句话说清要做什么 |
| `目的(Why)` | string | ✅ | 为什么要做（决定验收的"好坏"标准） |
| `范围(Scope)` | object `{含, 不含}` | ✅ | 含/不含本次覆盖的内容 |
| `验收标准(Accept)` | list[string] | ✅ | 可勾选的达成条件，至少 1 条 |
| `未知项(Unknown)` | list[string] | ✅（可空数组） | 会阻塞达标但用户没说的；空数组 = 无 |

---

## 模板

```markdown
# 政令任务书 · <政令标题>

- **意图(What)**：<一句话说清要做什么>

- **目的(Why)**：<为什么要做 / 这个任务为什么值得做 / 交付给谁用>

- **范围(Scope)**：
  - 含：<本次覆盖的内容，明确列举>
  - 不含：<明确排除的内容，至少 1 项防止加戏>

- **验收标准(Accept)**（可勾选的达成条件）：
  - [ ] <条件1：可机器或用户机械验证的判定>
  - [ ] <条件2>
  - [ ] <条件3>
  -（每条尽量用"含 X / 不含 Y / 数量 ≥ N / 文件存在于 Z 路径"这种可判定语言）

- **未知项(Unknown)**（会阻塞达标但用户没说的，可空）：
  - <缺素材？缺格式？缺 deadline？>
  - <若无 → 留空（推荐）或写"无">

---

*门禁硬约束：本任务书未经用户确认 → 流转司不得开始。*
*确认方式：用户口头/文字说"确认"或对 Accept 字段打勾均可。*
```

---

## 填写示例（最小可信）

```markdown
# 政令任务书 · 竞品分析示例

- **意图(What)**：A vs B 两家产品的功能/价格/用户口碑对比，1 份 md 分析 + 1 份汇报 PPT。

- **目的(Why)**：给老板汇报，需结论清晰、数据可信。

- **范围(Scope)**：
  - 含：A、B 双方案的 4 个维度对比；md + pptx 双产出。
  - 不含：市场规模预测、财务建模、未来 12 月走势预测。

- **验收标准(Accept)**：
  - [ ] md 含 A、B 双方案例维度对比
  - [ ] 关键数据有出处（链接/截图/公开年报）
  - [ ] PPT 页数 ≥ 10 且含"结论与建议"页
  - [ ] 交付路径落 `交付物/`

- **未知项(Unknown)**：（无）

---

*（用户已确认）*
```
